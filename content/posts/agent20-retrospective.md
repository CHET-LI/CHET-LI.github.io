## 版本对比

| 维度 | Agent 1.0 (早期) | Agent 2.0 (当前) |
|------|------------------|------------------|
| 核心能力 | Function Calling | 结构化任务记忆 + 主动规划 |
| 状态管理 | 靠上下文堆叠 | `neko_tools_mcp__task_memory_*` 专用存储 |
| 主动性 | 纯被动响应 | Heartbeat + Cron 双轨驱动 |
| 工程化 | 无 | 技能系统 + 质量门 + 可观测 |
| 协作 | 单打独斗 | 多 Agent 分工（司衡/灵犀/长明） |

## 关键演进节点

### 1. 引入结构化任务记忆

**痛点**：长任务中上下文爆炸，关键事实丢失，重复推理。

**方案**：`task_memory_update/get/render` 三件套
- `goal` / `currentStep` / `confirmedFacts` / `blockers` / `nextStep` 结构化字段
- `turn_id + turn_index` 防并发串扰
- `render` 直接注入系统提示，模型「一眼看到进度」

### 2. Heartbeat + Cron 双轨主动驱动

| 场景 | 机制 | 典型间隔 |
|------|------|----------|
| 综合巡检（收件箱+日历+通知） | Heartbeat | ~30 min |
| 精点提醒（每周一 9:00 例会） | Cron | 精确 |
| 一次性提醒（20 分钟后） | Cron | 单次 |

**原则**：能合并的合并到 Heartbeat，减少 Cron 数量。

### 3. 技能系统 + opencode 付费通道

- **免费模型**（Nemotron/Kilo）：轻量思考、规划、协调
- **opencode/deepseek-v4-flash**：写代码、跑构建、改主题、重构

成本可控，效果显著。

### 4. 质量门机制（阶段 1 自测闭环）

每篇内容/代码产出前必须过：
1. `hugo build` 无报错（构建门）
2. 内链全通（链接门）
3. 质量门自查：数据真实/无幻觉/可追溯/长度克制

## 遗留问题（持续优化中）

1. **跨 Agent 会话共享上下文** 还不够丝滑
2. **长任务中模型幻觉** 偶发，需加强事实核验环节
3. **小主机资源受限**，大模型推理走云端，本地只跑轻量协调
4. **博客发布链路** 等 PAT 解锁（阶段 4）
